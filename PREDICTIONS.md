## 2026-08-04 — can the temporal model produce SHARP, trial-appropriately-scattered bins matching Q's mean+variance? (registered before the run)

Test: train the sampling (temporal) decoder on real data with a MOMENT-MATCHING objective built on the law of total variance. Per-bin posteriors p_t have mean mu_t, variance s2_t. Target Q has linear moments mu_Q, s2_Q. sigma2_Q = Var_t[mu_t] (across-bin scatter) + E_t[s2_t] (within-bin width). Loss pushes: mean_t mu_t -> mu_Q (centre), Var_t[mu_t] -> s2_Q (scatter = full posterior variance => SAMPLING), E_t[s2_t] -> 0 (sharp bins). Held-out test split, 6 mice, H=8, vs a standard Jensen-KL head on the same split.

THE decisive readout is not whether the MARGINAL moments match (the loss forces that if the model has any freedom) but whether the per-trial SCATTER TRACKS the per-trial s2_Q on HELD-OUT trials — i.e. wide-posterior trials get wide bin-scatter, narrow get narrow. That is the difference between genuine trial-conditioned sampling and faking the marginal moments with a fixed scatter.

**Prior:** (a) the objective WILL drive the marginal moments to match — sharp bins (within-bin SD << Q's ~19 deg) with across-bin scatter ~ sigma_Q — because it has the freedom to; ~70%. (b) but per-trial held-out tracking of scatter vs s2_Q will be WEAK (r < ~0.3, slope << 1), because the diagnostic already showed the standard temporal decoder produces ~20 deg (Q-wide) bins with little cross-bin structure — the per-bin V1 activity in these 100 ms bins does not appear to carry trial-specific sample information. ~60%. (c) small chance (~15%) it genuinely tracks per-trial width -> real recoverable sampling structure, which would be a substantive positive. Falsifier for the pessimistic read: held-out scatter-vs-sigma_Q r > 0.4 with slope > 0.5. Also watch: the Jensen-average KL must not blow up — a decoder that matches moments but wrecks the posterior shape (KL >> chance) is moment-faking, not sampling.

**Outcome (2026-08-04, 6 mice, held-out) — NO, the temporal decoder cannot sample on real data; and it fails at the EASIER bar than I predicted.** Figure: `nn_decoder/figures/projflat/moment_sampling_test.png` (playground/moment_sampling_test.py).
- **Bins CAN be made sharp** — within-bin SD 4.9 deg mean vs Q's 19.3 deg (prediction (a) correct on sharpness). So the model can commit each bin to a narrow bump.
- **But the across-bin scatter CANNOT reach sigma_Q** — mean scatter/sigma_Q ~ 0.47, never >0.61 in any mouse, and this holds ON THE TRAINING SET too (train scatter ~= test scatter, e.g. 15.7 vs 15.4 deg at the ceiling), so it is a genuine representational limit, not overfitting. Prediction (a) said the marginal moments would match — WRONG on the scatter component: the loss pushes Var_t[mu_t] -> sigma2_Q and it caps at ~half even on train.
- **Consequence: forcing sharp bins destroys the posterior.** The Jensen average is ~8x over-peaked (avgMax 0.465 vs target 0.059) and KL(avg||Q) is **7.5x worse than chance** (mean, 6/6). The standard KL objective (broad bins, ~zero scatter, PPC) reproduces Q at ~chance/calibrated. So the variance can be carried WITHIN-instant (PPC) but not moved ACROSS-time as scattered samples.
- **Per-trial tracking weak — prediction (b) CONFIRMED.** held-out scatter-vs-sigma_Q r=0.35 mean, slope 0.09; two mice reach r~0.58 but slope stays <=0.17. The falsifier (r>0.4 AND slope>0.5) is not met in any mouse.
- **Net:** the law-of-total-variance test says V1 uncertainty in these bins is encoded as within-instant width, not across-time sampling — at least for this SBC readout (shared per-bin MLP, no explicit sampling dynamics), this data (second half, 100 ms bins), and using linear moments (which if anything OVER-state scatter via outliers). Scoring: (a) sharpness confirmed / scatter falsified; (b) confirmed; central answer (can it sample?) = no. A model with explicit temporal/latent sampling dynamics is untested and is the only obvious way the negative could be overturned.

**P1 — ↔ confirmed for spatial at wd=0, wrong on the loss value; the predicted cell itself is void.** The only clean flat cells are `*_wd0`. `A_flat_wd0` **spatial: peakiness 0.0603 vs target 0.0594 = 1.02×, normalised loss 0.948** (2/6 mice below chance) — against the evar baseline's 6.14× and 2.388. ## 2026-06-17 — train–val gap with dropout: does dropout regularise PCA's *overfitting* (even though it doesn't fix the over-sharpening)?  ↔ magnitude
**Registered (pre-resolution; p=0 baseline seen, p>0 still training):** the `monitor_val` knob finally lets us see the PCA train–val gap at patience 0. Prediction: dropout (p>0) will **shrink the train–val gap** (val_total−train_total at the final epoch) vs p=0 — because dropout *does* regularise capacity/overfitting — **even though** we already showed (2026-06-15) it does **not** reduce PCA's peakiness/over-sharpening. If both hold, the two are dissociated: PCA over-sharpens via loss-geometry drift, which is **not** the same thing as overfitting (a capacity/generalisation gap dropout can close). Confidence ~70%. Falsifier: if dropout leaves the gap unchanged, PCA's fit isn't capacity-limited here; if dropout shrinks the gap *and* fixes peakiness, the "over-sharpening ≠ overfitting" dissociation is wrong.
**Outcome (6 mice, PCA, patience 0 + monitor_val, all 3 levels) — ↔ over-predicted the effect:** the gap shrinks only **weakly and only for spatial** — spatial 0.0050→0.0048→**0.0044** (~12% at p=0.5, and via val *improving* 0.0062→0.0057, train flat ~0.0012); **temporal flat** 0.0055→0.0051→0.0053 (no trend). Far smaller than "dropout regularises overfitting" implies, and absent for temporal. (Baseline gap is real: val is 3–5× train spatial, ~2× temporal.)
**The richer finding (why the framing was slightly off):** the val PCA-loss curve is **flat, not rising** — it plateaus ~epoch 20 and stays there. So PCA is **not** overfitting in the textbook sense (train memorised, val degrading); the train–val gap is a **static offset baked into the location-only loss from early on**, not progressive overfitting that dropout could undo. And this curve is **not where the over-sharpening lives**: peakiness is invisible to the PCA loss (loss-blind subspace), so early-stop fixes peakiness *despite* a flat val-loss (the over-sharpening drifts up monotonically with epochs even as val-PCA-loss is flat), while dropout barely moves either.
**Lesson:** "train–val gap" and "over-sharpening" are **different objects** — the gap is a static loss-geometry offset (dropout-insensitive, doesn't grow with epochs), the over-sharpening is a monotonic drift in the loss-blind subspace (early-stop-sensitive, smoothness-fixable). Don't conflate the generalisation gap with the calibration pathology. Still consistent with the loss-geometry account (capacity knobs don't fix the calibration problem); the prediction's *spirit* (dropout ≠ the fix) held, its *mechanism* (a closable overfitting gap) didn't.
