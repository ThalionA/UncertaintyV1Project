## 1. Bugs (B)

### B1. Shuffle-control decoders see REAL validation targets when `val_frac > 0` [verified] — HIGH
- **Files**: `run_experiment.py:549-552` (Y_val built from real `target_distr_`), `:565`
  (only `Y_train_in` permuted), `:637-661` (one `training_params` dict, containing the real
  `X_val_in`/`Y_val_in`, passed verbatim to all four arms incl. both shuffle arms).
- **Problem**: with `val_frac>0`, the shuffle arms are early-stopped and (since the
  2026-07-16 fix, `restart_selection='val'`) restart-selected on **unshuffled** validation
  targets — the null model is selected on real-data signal. And when `val_frac=0,
  patience>0`, `fit_model` carves val from the already-shuffled tensors
  (`nn_classifier.py:546-554`), so val IS shuffled — two different shuffle nulls depending
  on val config. Any shuffle-normalised ratio compared across runs with different val
  configs mixes nulls. Effect size on published ratios **unmeasured**; which runs are
  exposed (val_frac>0 + shuffle-normalised claims) needs a config census before any number
  is re-stated.
- **Solution**: build a shuffled `Y_val_in` (same trial-permutation semantics) for the
  shuffle arms; document the null in GOTCHAS; census on-disk `config.yaml`s for exposure.
  NOTE: changes shuffle results going forward — same comparability concern as July's C3, so
  decide fix-vs-document deliberately, not by default.
- **Confidence**: high (construct); unmeasured (impact).

### B2. `Config.random_state` is a dead knob [verified] — HIGH
- **Files**: `training/config.py:233` (field), `to_legacy_dict` (absent),
  `run_experiment.py:463,467,482` (hardcodes `random_state=42`).
- **Problem**: `Config(random_state=7)` silently yields the same split as 42 — a
  split-robustness sweep would report fake stability. No existing run is wrong (default==42),
  but it's the exact `to_legacy_dict` plumbing-gap class the repo has been burned by.
- **Solution**: thread through `to_legacy_dict` → 3 call sites; default unchanged → no-op
  for production. Extend the plumbing test (see B9).
- **Confidence**: high.

### B3. `synthetic_ppc` / `synthetic_sbc` target branch crashes [verified] — HIGH
- **Files**: `run_experiment.py:412-417`; `utils.py:222,262` (generators return
  `(likelihoods, posteriors)` tuples).
- **Problem**: the tuple is assigned whole to `raw_targets`; `raw_targets.T` at `:496`
  raises `AttributeError`. The documented synthetic-target control is unusable. Loud crash,
  so no silent wrong science — a regression from when generators returned one array.
- **Solution**: `raw_targets = generated_targets[1]`; add a smoke test for both branches.
- **Confidence**: high.

### B4. Silent CE fall-through in both loss dispatchers [verified] — MED
- **Files**: `nn_classifier.py:255-256` (`custom_loss_all_H`), `:431-432`
  (`fit_loss_per_trial`) — CE is the bare `else`.
- **Problem**: a typo'd/wrong-case loss string (`'kl'`, `'Brier'`) silently trains CE under
  the wrong label — the silent-ReLU footgun pattern, which the activation registry already
  fixed (`:110-113`) but the loss dispatch didn't. Config-driven runs are guarded; direct
  importers (sweep/diagnostic scripts, of which there are many) are not.
- **Solution**: explicit `'CE'` branch + `else: raise ValueError`, both sites; tiny test.
- **Confidence**: high.

### B5. No guard for Wasserstein / `smooth_lambda` on the 72-bin circular support [verified] — MED
- **Files**: `training/config.py:69-70` (comment says "Do NOT pair"), `__post_init__`
  (no check); `nn_classifier.py:45-53` (linear cumsum), `:459` (no 71↔0 wrap term).
- **Problem**: an `io_hmm_pkl` config with either knob runs to completion with silently
  wrong loss geometry (mass across the circular wrap priced maximally instead of minimally).
- **Solution**: one `raise` in `__post_init__`; test.
- **Confidence**: high (guard absent); med (someone trips it).

### B6. Two different default pkl paths for the same knob [verified] — MED
- **Files**: `training/config.py:75` (`data/fitted_data_and_posteriors_hmm.pkl`) vs
  `run_experiment.py:368` fallback (`data/fitted_data_and_posteriors.pkl` — the older
  non-HMM file).
- **Problem**: a hand-built legacy dict with `target_source='io_hmm_pkl'` and no explicit
  path silently trains on non-HMM marginals labelled like an HMM run.
- **Solution**: single constant (home: `paths.py`), both sites import it.
- **Confidence**: high.

### B7. Greedy barcode alignment can mis-assign trials near a dropped trial [agent] — MED
- **Files**: `io_hmm_data.py:459-472` (first-match greedy on `(ori, disp, contrast)`),
  `:488` (0.95 choice-agreement floor can't catch single-trial slips).
- **Problem**: when a dropped pkl trial and the true match share a barcode in the same
  neighbourhood, an export trial silently receives a different trial's posterior.
  Exposure ~a handful of trials/mouse; incidence unmeasured.
- **Solution**: strengthen the invariant (match on choice where defined / assert dropped
  indices are barcode-unique in a window), and add the missing tests (S2 — `io_hmm_data.py`
  currently has ZERO tests).
- **Confidence**: med.

### B8. `figsave.save_fig` cap is best-effort and its log misreports dpi [agent, matches observed failures] — MED
- **Files**: `figsave.py:64-73` (`except Exception: dpi_fit = dpi` — cap silently dropped),
  `:89` (prints nominal `dpi`, not the `dpi_fit` actually used).
- **Problem**: matches the 2026-08-23 measured failure (6/13 PNGs at 1603–1822 px). No
  post-save pixel check exists; the log violates "measure the object".
- **Solution**: post-save `PIL`/`imagesize` check + downscale-retry; print `dpi_fit`;
  first-ever tests for `figsave` (S2).
- **Confidence**: high (construct).

### B9. The plumbing regression test is stale [agent, mechanism verified via B2] — MED
- **Files**: `tests/test_training_config.py` (`needed` set frozen at 21 keys) vs
  `run_animal_decoder`'s current reads (16+ newer keys incl. `restart_selection`, `seed`,
  `smooth_lambda`, the `io_hmm_*` triple).
- **Problem**: the test exists to catch `to_legacy_dict` omissions and would currently miss
  the exact regression class it was written for (and did not catch B2).
- **Solution**: derive the needed-key set from what `run_animal_decoder` actually reads (or
  at minimum extend + add the converse direction: every Config field lands in the dict or is
  explicitly listed as recorded-only).
- **Confidence**: high.

### B10. Low-severity cluster [agent] — take selectively
(a) `utils.py:35,45,375` seed the **global** numpy RNG (process-wide side effect; GOTCHAS
covers the single-permutation aspect, not the side effect); (b) `flat_evar`/`shape_lambda`/
`evar_alpha` exclusivity by silent `if/elif` (`run_experiment.py:209-221`); (c) `_PRESETS`
shallow-copies `hidden_sizes` (`training/config.py:616-618`) — in-place mutation corrupts
the module-global preset; (d) train/val "total" curves omit `smooth_lambda`'s term
(`nn_classifier.py:630-676` vs `:584-586`); (e) NaN val loss defeats early stopping →
silently returns final not best weights (`:605`); (f) final-epoch weight snapshot missed
under ES (`:663-664`); (g) `get_model_probabilities` unknown model_type →
`UnboundLocalError` (`:161-169`); (h) `'temp' in key` substring routing
(`run_experiment.py:257`); (i) `time_binned_ppc.fit_pca_basis` uses condition_mean fit on
ALL trials while production is all_trials/train-only — caption mislabel risk
(`time_binned_ppc.py:234-256`); (j) `io_hmm_data._install_stubs` clobbers
`sys.modules['jax']` unconditionally.
